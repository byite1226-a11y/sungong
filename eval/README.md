# Phase A — AI 숙제검사 판독 정확도 평가 하네스

설계서 v3 §8-2의 크리티컬 패스. 사진이 모이는 대로 바로 측정할 수 있게 미리 짜 둔 도구입니다.
**Flutter와 무관하게 지금 돌 수 있습니다.**

## 1. 평가셋 수집 (30~50장)

본인·주변 학생의 채점 완료 숙제를 촬영합니다. 다음이 골고루 섞이게 **의도적으로** 수집하세요:

- **과목** — 수학(식 위주)과 국어·영어(지문 위주)는 레이아웃이 완전히 다릅니다
- **마크** — ○ 편중을 피하고 사선·△·☆를 일부러 채웁니다. **△가 가장 부족합니다**
- **풀이** — **빈칸 문항**과 **"답만 적힌" 문항**을 반드시 포함합니다 (work 축 검증용)
- **조건** — 밝은 곳 / 어두운 곳 / 그림자 / 비스듬한 각도 / 필기가 겹친 경우
- **문항 수** — 10문항 이하 / 20문항 / 50문항 이상

사진은 `eval/photos/` 에 넣으세요 (jpg·png·webp).

## 2. 정답 라벨 작성

사람이 직접 만듭니다. `labels.example.json` 을 복사해 `labels.json` 으로:

```json
{
  "IMG_0001.jpg": {
    "1": { "mark": "circle",   "work": "solved" },
    "2": { "mark": "slash",    "work": "solved" },
    "3": { "mark": "unmarked", "work": "blank"  }
  }
}
```

- `mark`: `circle` ○ · `slash` 사선 · `triangle` △ · `star` ☆ · `unmarked` 표시 없음
- `work`: `solved` 손글씨 풀이 있음 · `blank` 손글씨 없음 · `partial` 일부만

## 3. 판독 실행

```bash
cd eval && npm install
export ANTHROPIC_API_KEY=...        # Edge Function에 들어갈 키와 동일 계열
node read.mjs --photos photos --model claude-opus-5 --prompt v1
# → runs/<시각>-<모델>-<프롬프트버전>.json
```

여러 모델을 나란히 재려면 `--model` 만 바꿔 반복 실행합니다.
**정확도 먼저, 단가는 임계치를 넘은 모델끼리만 비교합니다** (v3 §8-2).

## 4. 채점

```bash
node measure.mjs --run runs/<파일>.json --labels labels.json
```

네 지표와 게이트 판정이 출력됩니다:

| 지표 | 임계치 |
|---|---|
| 문항–마크 결합 정확도 | **≥ 90%** |
| 사선 ↔ △ 혼동률 | **≤ 5%** |
| 문항 번호 누락률 | **≤ 5%** |
| 풀이 흔적(work) 정확도 | **≥ 95%** |

지표 정의:
- **결합 정확도** — 라벨된 전 문항 중 mark가 정확히 일치한 비율. **판독이 누락된 문항은 오답으로 셉니다.**
- **혼동률** — 라벨이 slash 또는 triangle인 문항 중, 서로 반대로 읽은 비율.
- **누락률** — 라벨된 문항 중 판독 결과에 그 번호가 아예 없는 비율.
- **work 정확도** — 판독된 문항 중 work가 일치한 비율 (누락은 위 누락률이 잡습니다).

## 5. 미달 시

축소하지 않고 보완합니다 (v3 §8-2): 프롬프트 개선(`read.mjs`의 `PROMPTS`에 v2 추가) →
모델 교체 → 촬영 가이드 강화 → 재측정. **3차 시도 후에도 미달이면 숫자를 그대로 보고하고
결정을 받습니다.**

## 알려진 한계 (문서화된 정상 동작)

- **"답만 적힌" 문항은 `solved`로 읽힙니다.** work 판정은 풀이 과정이 아니라 필기 유무만
  봅니다. `circle + blank` 잡기는 빈칸일 때만 성립하고, 답 한 줄이라도 쓰면 solved입니다.
  학생 확인 화면에서 고칠 수 있게 하는 것이 대응입니다 (v3 §11).
